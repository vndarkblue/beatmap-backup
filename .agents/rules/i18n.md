# Internationalization (i18n) Rules

The application offers complete support for 3 languages: English (`en`), Vietnamese (`vi`), and Japanese (`ja`). Consistency across dictionaries is strictly enforced by automated test suites.

## 1. Mandatory Rules When Adding / Modifying UI Strings

1. **Never hardcode displayed text**:
   - Every string visible to the user (button labels, titles, descriptions, error messages, toast notifications) must pass through `t('key')` or `$t('key')`.
2. **Language Triangle Parity (Strict Parity)**:
   - When adding or modifying a translation key, **you must update all 3 locale files concurrently**:
     - `src/renderer/src/i18n/locales/en.json`
     - `src/renderer/src/i18n/locales/vi.json`
     - `src/renderer/src/i18n/locales/ja.json`
   - If an exact Vietnamese or Japanese translation is not yet available, supply a temporary translation or fallback English string, but **never leave a key missing or an empty string**.
3. **Variable / Placeholder Consistency**:
   - Every interpolation placeholder formatted as `{variable_name}` (e.g., `{count}`, `{percent}`, `{path}`) must **match 100%** across all 3 languages.
   - Any placeholder discrepancy will cause `tests/renderer/i18n.test.ts` to FAIL.

## 2. Key Hierarchy Organization

JSON files are structured by functional domain and view:

```json
{
  "common": { "ok": "OK", "cancel": "Cancel", ... },
  "nav": { "backup": "Backup", "download": "Download", ... },
  "backup": { ... },
  "download": { ... },
  "filter": { ... },
  "settings": { ... }
}
```

- Avoid sprawling flat keys at the root level; group hierarchically by usage context.
- Use semantic key naming: e.g., `settings.database.sync_btn` instead of `btn1`.

## 3. Translation Tooling (Scripts)

When collaborating on bulk translations:

- **Export to CSV**: `npm run i18n:export`
  - Runs `scripts/i18n-export-csv.js`, aggregating keys from all 3 JSON files into a CSV spreadsheet.
- **Import from CSV**: `npm run i18n:import`
  - Runs `scripts/i18n-import-csv.js`, synchronizing translations from CSV back into respective JSON files.

## 4. Verification Check

After modifying any i18n string, immediately run:

```powershell
npx vitest run tests/renderer/i18n.test.ts
```

To ensure:

- All 3 languages contain identical key sets.
- No string is left empty (`""`).
- All interpolation placeholders `{placeholder}` match across all locales.
